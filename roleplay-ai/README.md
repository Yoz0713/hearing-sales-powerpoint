# roleplay-ai — QR 掃碼 × AI 難搞客人角色扮演

課程 p43 用的線上角色扮演。學員掃 QR → 讀背景故事 → 和「AI 演員扮演的難搞客人（陳先生）」對話 → 對話結束後看講師回饋。

**這是獨立於簡報 deck 的小 App**，不影響 deck 的靜態建置。

## 四個階段

| 階段 | 條件 | 陳先生 |
| --- | --- | --- |
| 1 防備 | — | 短、冷、擋話（「太貴了」「我再考慮看看」） |
| 2 鬆口 `open` | 問到**生活情境**，並讓陳先生明說**外觀／身份標籤焦慮** | 說出怕被朋友看到、顯老或被認為不中用 |
| 3 心防放下 `ready` | 學員**具體回應**外觀／身份標籤焦慮 | 語氣放軟，但停在原地等對方開口 |
| 4 答應 `accepted` | 學員**主動邀約**（試戴／約時間／帶太太來） | 答應，這一輪收尾 |

「怕沒效果」是可被探索與處理的次要疑慮，但**不能取代外觀／身份標籤這一關**。只處理效果後邀請
試聽，陳先生會肯定對方有理解他，但仍婉拒。生活痛點建立後，若學員連續兩次有效探索仍沒碰到
核心顧慮，陳先生會給一句「戴那個出去總覺得怪怪的」之類的含蓄提示；學員仍須追問，讓他明確
說出怕被朋友看到或顯老，提示本身不算過關。

**設計上的鐵則：下一步永遠由學員提出。** 陳先生任何階段都不會自己說「那我試戴看看」，也不能用
「那接下來呢？」之類的話暗示（`persona.ts` 的 `NEVER_INITIATE`）。時機未到就邀約 → 婉拒，
並記進 `earlyInvites` 供回饋報告點名。

階段二的閘門只看**陳先生這一則有沒有真的說出口**（`identityConcernDisclosed`），不看學員是用
問句探索、還是用同理或舉例把話帶出來的。這裡曾經多押一個 `identityProbe`，結果學員說「這就
像戴眼鏡一樣」、陳先生當場回「怕人家看到會覺得我老了」，畫面上已經講破、狀態機卻還停在
「尚未揭露」，之後 `statusOf` 一直送錯階段，這一關就再也開不了。`identityProbe` 現在只餵給
`statusOf` 決定提示節奏與講師點評，不當閘門；防跳關由「生活情境必須在更早的回合成立」負責。

階段三的判定刻意要求「這一則之前就已鬆口」（`gate.ts` 的 `mergeVerdict`），因為顧慮是在鬆口
那一則才說出口的，同一則不可能已經回應到它 —— 藉此擋掉跳關。但學員在揭露的同一則就接住
（先同理、陳先生才講破）是很自然的順序，那句話不該白費：`GateState.pendingAddressed` 把它
寄放一回合，下一則非離題訊息自動兌現成「已接住」。離題回合只會原封不動帶過去，不兌現也不清掉。

## 綜合評等

報告頁的評等由 `src/rating.ts` 純函式算出，**不經過 API** —— 講師點評抓不到時評等照樣看得到。
三軸加權：里程碑 50%、對話精準度 30%、推銷控制力 20%；90/75/60 分切 S/A/B/C。

兩個容易寫錯的地方：

- **對話精準度要先看有沒有走完全程。** 直接用回合數分級的話，第 3 回合就放棄的學員會因為
  「≤ 8 回合」拿到滿分，等於獎勵放棄。沒讓陳先生點頭一律 40 分。
- **推銷率的分母要扣掉離題回合**，否則亂打一通會稀釋掉真實表現。

平均思考時間只呈現、不計分（想久不是錯）。單回合超過 2 分鐘視為離開畫面，整筆不列入平均 ——
一次 20 分鐘的樣本會毀掉平均，夾到上限一樣失真。

時間與次數統計放在 `src/metrics.ts`，**刻意不放進 `GateState`**：`INITIAL_GATE_STATE` 是模組層級
常數，把 `Date.now()` 寫進去會被凍結在載入當下，`restart()` 之後計時全錯；而且 `mergeVerdict`
是不看時間的純函式，混入時間戳就測不動了。

## 課後回饋

對話結束（答應邀約，或用完 `MAX_TURNS` 次發言）後按「看講師回饋」，會用整份逐字稿再打一次
Gemini，產出總評 / 你做對的地方（引用學員原句）/ 下次可以更好（給可照抄的替代說法）/ 關鍵訊號。
提示與 schema 分別在 `persona.ts` 的 `buildReviewPrompt` 與 `gate.ts` 的 `REVIEW_SCHEMA`。

## 逐字稿（報告頁）

報告頁最後收合著一份逐字稿（`src/Transcript.tsx`）。它**刻意不重播對話畫面的左右氣泡** ——
回顧時這是一份文件而不是一場對話，所以改成單欄劇本式排版，學員自己講的話用實色、陳先生的
回覆用次要色，方便一路往下掃「我哪一句讓事情動了」。

左側脊線是這一區唯一有資訊量的裝飾：

- **節點**＝里程碑落在哪一句，序號沿用報告頁上方 chip 的同一組數字（上方是總結，下方是落點）。
- **節點間距**＝推進那一關花了幾輪。
- **實線只存在於第一個到最後一個里程碑之間**；開場到第一個里程碑之間還沒動起來、最後一個
  之後是空轉，兩頭都畫虛線。末端走完是實心收合，沒走完就留一個空心環敞在那裡。

落點記在 `GateState.milestoneTurns`（四個 `messages` 索引），由 `mergeVerdict` 的 `turn` 參數寫入。
記的是**學員那一則**而不是陳先生的回覆 —— 要看的是自己哪句話有效。`pendingAddressed` 存的
是索引而非布林，就是為了讓延後兌現的「回應他的擔心」把功勞記回當初說那句同理的那一則，
而不是兌現的那一則。

## 架構

```
手機 → 前端(React/Vite) → /api/chat 代理函式 → Google Gemini API
                            └ 藏 GEMINI_API_KEY，只轉發，不含業務邏輯
```

- 人設在 `src/persona.ts`、關卡機制在 `src/gate.ts`（都在前端）。
- 任務簡報內容在 `persona.ts` 的 `MISSION`；`src/MissionBrief.tsx` 同時給進場的整頁簡報
  （`brief--page`）與對話中拉起的任務面板（`brief--sheet`）用，兩者只差字級與排列順序（CSS `order`）。
- 手機鍵盤：iOS Safari 叫出鍵盤時不縮 layout viewport，只把整頁往上捲，會把 header 推出畫面、
  對話區被蓋掉。`src/useViewportFit.ts` 改用 `visualViewport` 寫入 `--app-h` / `--app-top`，
  對話畫面用 `position: fixed` 貼齊真正可見的區域。改動對話畫面高度時要一起看這支。
- `api/chat.ts` 是唯一碰金鑰的地方；前端與 QR 都看不到金鑰。
- 每則使用者訊息一次呼叫，結構化 JSON 同時回傳八個布林判定 + 陳先生的回覆。
  判定由前端累加成階段狀態，再寫回下一次的 systemInstruction。
- 判定分三類：`lifeContext` / `concernProbe` / `identityConcernDisclosed` /
  `identityConcernAddressed` / `invited` 形成關卡進度；`identityProbe` 不開門，只用來決定
  揭露提示的節奏與講師點評；`notPushy` / `offTopic` 只反映最新一則，供教練提示用。
  `offTopic` 為真時 `mergeVerdict` 直接擋掉所有正向判定 —— 亂打一通不該解鎖進度。
- 關卡要求生活情境先在較早回合成立；同一句直接猜完生活痛點與外觀顧慮不算建立信任。

## 模型設定

`api/chat.ts` 的 `MODEL` 常數目前為 `gemini-3.6-flash`。
**部署前請於 Google AI Studio / Gemini API 文件確認正式 model ID**，不對就改這一行。

原本用的是 `gemini-3.5-flash-lite`，但它對「兩次有效探索才給提示 + 一串禁字」這種多層負向
約束遵從度不夠，常在第一次一般探索就把「戴那個出去怪怪的」講破，兩段式揭露的節奏就沒了。
`persona.ts` 的 `finalGuardOf` 是同一個問題的另一半保險：把禁字提醒放到系統提示的最後一行，
而且只在真正要守的那個回合出現。

### maxOutputTokens 是「思考 + 回覆」共用的

換到 Gemini 3.x 這種會思考的模型後，這一格不再等於回覆長度。實測 `gemini-3.6-flash`：

| 呼叫 | thoughtsTokenCount | 回覆 tokens |
| --- | --- | --- |
| 對話（一句話 + 八個布林） | 770 ~ 1400 | 約 100 |
| 課後點評（四段結構化文字） | 約 1400 | 約 640 |

舊版寫死 `OUT_TOKENS = 1400`，點評的思考就把額度用光，只吐出 41 個 token 就
`finishReason: MAX_TOKENS`，JSON 被截在半句話 → `parseReview` 直接爆掉 → 報告頁永遠顯示
「點評這次沒有載入」。額度現在由前端依用途指定（`src/api.ts` 的 `CONVERSE_OUT_TOKENS` /
`REVIEW_OUT_TOKENS`），代理函式只夾限到 `MAX_OUT_TOKENS`。

代理函式會把 `finishReason` 一起回傳，前端遇到 `MAX_TOKENS` 就直接講「被截斷」，不要讓下游
拿半截 JSON 再丟一個看不懂的解析錯誤。

`thinkingConfig.thinkingBudget: 0` 在 3.x 會回 400（那是 2.5 的參數）；`thinkingLevel: 'low'`
可用且思考直接歸零，但關卡的八個布林判定就是靠思考撐品質的，**刻意不關**。

## 本機開發

```bash
cd roleplay-ai
npm install
cp .env.example .env.local   # 填入 GEMINI_API_KEY
npx vercel dev               # 同時起前端與 /api 代理（需要 Vercel CLI）
```

只想跑前端 UI（不連 API）可用 `npm run dev`，但對話會失敗（因為沒有 /api）。

## 部署（Vercel）

1. 在 Vercel 新增專案，**Root Directory 設為 `roleplay-ai`**。
2. 環境變數加入 `GEMINI_API_KEY`（Google 金鑰）。
3. 部署後取得網址 → 拿去產生簡報 p43 的 QR code。

其他平台（Netlify / Cloudflare）亦可，需把 `api/chat.ts` 改成該平台的 function 慣例。

## 驗證

- 一開始亂問或急著推銷 → 陳先生維持防備、只回「再考慮看看」。
- 問到生活情境，再讓陳先生明說怕被朋友看到、顯老或被貼標籤（上方 chip 依序亮起）→ 陳先生明顯鬆口。
- 只問並處理「怕沒效果」後邀請試聽 → 陳先生肯定被理解，但仍婉拒，真正顧慮 chip 不亮。
- 第二次一般探索仍沒問到核心顧慮 → 陳先生只給含蓄外觀提示；追問後才明說並點亮 chip。
  此時教練提示會說「他剛剛透露了一點什麼」，提醒學員追問而不是急著給方案。
- 不用問句、改用同理把話帶出來（「這就像戴眼鏡一樣」）→ 只要陳先生這一則真的說出怕被朋友
  看到、顯老，第二個 chip 一樣要亮；下一則再兌現「回應他的擔心」。
- 回應他的外觀／身份標籤焦慮後 → 語氣放軟，但**不會**自己提試戴或帶太太來；教練提示會叫你主動開口。
- 鬆口前就邀約 → 被婉拒，chip 不亮。
- 結束後按「看講師回饋」→ 出現總評與逐條點評。
- 輸入無厘頭的話（「我愛你」）→ 陳先生困惑地拉回正題，教練提示顯示「陳先生聽不懂這句話…」，
  進度 chip 不會亮，也不會跳出推銷提示。
- 開發者工具 Network / Source 看不到金鑰。
